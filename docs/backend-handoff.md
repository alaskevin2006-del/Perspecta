## 工程决定及代价

- 独立 `backend/`，避免提前决定前端框架。代价是前端需要同源代理；可按既有 Web Request/Response handler 加薄路由适配。
- 正式引用规则优先于示例中 `m6 -> m4` 的错误值，fixture 修为 `m6 -> m1`。字段不变，示例一处值有意不同。
- 使用 JSON mode 加服务端严格校验，兼容支持该参数的 Chat Completions 服务；JSON mode 不保证模型遵循 schema，校验失败直接返回 502，无自动付费修复。
- 不选择未获确认的真实模型与价格，费用只记录上游返回值（没有则 null），不会虚报实时生成或 token。
- 用户已指定只推送独立分支，按此执行，不另外创建 PR 或合并。独立克隆保留供继续联调。

## 独立审阅中的边界决定

以下均在本次演示范围内接受，代价明确保留：

- 缺上游 usage 按契约返回 null，保留预留额；代价是缺计数时预算更保守。
- 60–140 汉字、观点差异和事实准确性由提示词引导并人工验收；代价是结构通过不代表语义质量通过。
- 一轮内不强制遵守用户选择顺序，只保证轮次分组及每人一条；前端按 roleId 显示，不能依赖数组位置匹配角色。
- 多余请求字段忽略并排除出提示词；多余提供商 envelope 丢弃，核心生成结果仍严格拒绝多余字段；代价是没有扩展请求参数通道。
- mock 内容与固定 ID 明确标识；共享的同议题/角色并发提交会一起受限；代价是不同用户可能需要稍后重试。
- socket 身份、固定窗口和进程本地预算按文档执行；代价是代理后共享桶、重启重置、多实例没有共享预算。
- persona 来源与可选元数据由画像组审阅；代价是后端不会替资料团队验证事实。
- 严格 Content-Type、登录鉴权及分布式基础设施不进入演示首版；公开部署前须重新评估运行环境。
- Docker 运行未验证；Flash 在原提示词下单次成功，但改后提示词和全面质量未验收，不宣称生产可用。
- 初次交付只有 handler 层取消测试；后续新增实际 socket 断开集成回归，已验证上游取消并释放名额。
