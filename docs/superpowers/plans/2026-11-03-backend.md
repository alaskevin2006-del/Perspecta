# Perspecta backend implementation plan

> Execution: implement inline in this isolated clone on `feat/api`; user authorized autonomous planning, implementation and later normal push to an independent backend branch. Use test-driven-development and verification-before-completion. No main modifications/merge, force push, deploy, credentials, frontend or persona edits.

**Goal:** deliver the three locked v0.1 API endpoints, mock first, then a single-call model adapter with validation and bounded resource use.

**Architecture:** self-contained `backend/` Node.js ES modules with no third-party runtime dependencies. HTTP adapter delegates to a Web Request/Response application; catalog JSON is replaceable. A frontend development proxy or production reverse proxy keeps `/api` same-origin without editing frontend files.

**Tech stack:** Node.js 22+, built-in HTTP/fetch/test. **Spec:** `.doc/00_开工说明.md`, `.doc/01_PRD_产品需求.md`, `.doc/02_API_联调契约.md`, `.doc/03_人物画像与讨论规则.md` (all read completely).

## Global constraints

- Exact routes and camelCase response fields; topic trimmed 10–300 Unicode characters; 2–3 unique allowlisted role IDs.
- Exactly two messages per selected role, grouped by round; every round-two reply references a different role's first-round message.
- One upstream call, no automatic retries; model generates only messages and summary; server owns ID, topic and usage.
- No transcript storage or transcript/credential logging; mock clearly identified outside the locked response body.
- Role data uses the supplied prototypes, pending persona team delivery; no original persona work.

## Review focus

1. Two-role subsets and arbitrary selection order produce valid cross-role references.
2. JSON primitives, malformed UTF-8/JSON, unknown/duplicate roles, Unicode boundary lengths and oversized bodies fail before model calls.
3. Upstream schema drift, bad references, extra fields and truncation never escape as success; missing usage must stay null as the contract permits.
4. Concurrent duplicates, saturation, timeouts and disconnects release active slots while preserving conservative cost accounting.
5. Client identity cannot be spoofed by forwarded headers; in-memory controls remain bounded and explicitly single-process.
