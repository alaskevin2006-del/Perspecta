## 无需付费的联调顺序

1. 后端以显式 mock 启动（见 deployment-runbook）；前端同源 `/api` 代理到 127.0.0.1:3001，保留前缀，不开放浏览器 API Key。
2. 先运行 `API_BASE_URL=http://127.0.0.1:3001 npm run health`，再检查 GET roles/topics；前端不按固定数组位置推断角色。
3. 验证三种议题输入、10–300 字符、2/3/4 个不同角色和非法输入提示；POST 只发 `{topic,roleIds}`，不发客户端画像。
4. mock 文案固定来自绩点示例，对其他议题只是接口占位，不能当真实回答；页面显著标注模拟数据。
5. messages 按返回顺序展示，使用 id/roleId/round/replyTo 关联；先第一轮后第二轮，不以 roleIds 下标猜回复对象。
6. 展示 summary 的四个非空数组及 usage（缺失计数可为 null）；复制与 Markdown 导出为前端职责。
7. 在前端本地测试中模拟 400/429/502/504/500 的统一 error 结构：失败保留输入、结束加载、允许用户明确重试；生成中禁用重复按钮。不要为了错误画面触发真实模型。
8. 用明确标记的历史 JSON 检查稳定回放；实时失败不能静默换成历史成功。历史候选需产品负责人批准后才作为最终展示内容。

## 安全及兼容边界

- 同源优先，后端没有跨源 CORS 放开；不能因请求失败把 Key 放入前端环境变量、URL或浏览器请求头。
- 模型发言按不可信文本渲染，保留默认转义；若引入 Markdown/HTML 渲染，由前端确认其清理方案，避免直接插入原始 HTML。
- `avatar` 是本地资产键，不是远程图片 URL；卡片身份以服务端 role id 为准。新增画像数据不应要求改 API 字段。
- 整体等待时限给后端默认 45 秒模型超时留传输余量；不无限轮询、不自动 POST 重试。
- 502 包括结构、引用、明确引语来源或计数异常；无论具体错误，前端只依赖既有 code/message，不解析供应商错误。
- health PASS 不是内容、供应商或额度验收。模型额度耗尽时进程仍可健康，前端应正确显示429而非自动刷新重启。
