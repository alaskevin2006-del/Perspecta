2. **下一次真实测试的调用次数与费用上限。** 此前一次及额外三次授权均已使用完，不自动沿用；新生成须另行确认。本地 token 预算不是货币账单硬上限。
3. **目标环境的凭据注入位置及授权。** 本机 `.env.local` 仅供该用户使用；部署环境还需选择服务端密钥入口并获准注入，不会把本机文件提交、复制到镜像或发送给队友。

后续真实请求仍须相应授权，失败不会自动重试。已有历史真实样本及工程质量问题清单，见 `backend/examples/README.md`；默认 mock 仍是文档占位数据，二者明确区分。

## 无需真实凭据即可执行的启动流程

在具备 Node.js 22+ 的目标机器，先在本地或已有测试环境验证 mock：

```sh
cd backend
DEBATE_MODE=mock HOST=127.0.0.1 PORT=3001 node src/server.js
```

另一个终端：

```sh
cd backend
npm test
API_BASE_URL=http://127.0.0.1:3001 npm run smoke
```

健康检查只请求 `GET /api/roles`，不会触发模型。容器已默认监听 `0.0.0.0:3001`，直接 Node 模式默认仅绑定本机。受管理平台应注入其指定 PORT；入口上游超时应超过默认 45 秒生成超时并留出传输余量。

前端代理必须保留 `/api` 前缀和 JSON 响应。前端在生成中禁用重复提交，失败保留输入，由用户手动重试；mock 模式显示“模拟数据”。同源代理测试只验证传输约定，不证明具体前端框架配置或实际部署已完成。

对于容器平台，在有 Docker 的环境另行执行 README 中的构建/启动命令，检查镜像、健康检查、环境变量和 SIGTERM；本机不能用静态 Dockerfile 检查替代实际运行。
