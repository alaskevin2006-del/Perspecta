## 2. 本机零费用预检

服务终端（从仓库根目录开始，清空继承环境，不加载任何 Key 文件）：

```sh
cd backend
env -i PATH="$PATH" DEBATE_MODE=mock HOST=127.0.0.1 PORT=3001 node src/server.js
```

另一个终端（同样从仓库根目录开始）：

```sh
cd backend
API_BASE_URL=http://127.0.0.1:3001 npm run health
API_BASE_URL=http://127.0.0.1:3001 npm run smoke
```

health 永远只 GET `/api/roles` 和 `/api/topics`，不带任何凭据、不 POST、不测供应商连通性；PASS 表示进程/目录契约可用，不表示 Key、模型、额度或内容质量正常。它检查模式一致、no-store、目录结构与 ID，失败只输出固定错误码，不回显目标 URL/正文。

smoke 会 POST：仅在明确 mock 时用于本轮零费用验证。发现 live 且没有 `--live` 会停止；当前没有新真实调用授权，因此**不要加 `--live`**。检查后 Ctrl+C 停止本机临时进程。

### health 失败排查

| code | 排查方向（不输出秘密或原始正文） |
| --- | --- |
| INVALID_HEALTH_TARGET | HTTPS 或回环 HTTP 根地址；不能带用户信息、查询、片段或子路径 |
| HEALTH_HTTP_ERROR | 查看输出的数字状态码，确认目录接口和代理路由，不用模型生成探测 |
| HEALTH_CONTRACT_ERROR | 检查 JSON 结构、模式头、no-store 和是否被替换成 HTML |
| HEALTH_MODE_MISMATCH | 两个目录请求到了不同模式实例，核对发布/代理/缓存 |
| HEALTH_TRANSPORT_ERROR | DNS、TLS、超时或重定向等传输错误；只记录安全诊断，不回传 URL 内秘密 |

## 3. 目标环境先用 mock（须先有部署授权）

- [ ] Node 直接运行默认绑定 127.0.0.1，若平台需要其他监听地址/PORT，由平台隔离和入口方案明确后设置。
- [ ] 容器内监听 0.0.0.0 不等于批准公开宿主端口。自管本机/服务器 mock 示例绑定回环：

```sh
# 从仓库根目录执行，仅供未来具备 Docker 并获准的环境；本机未执行。
docker build -t perspecta-api:reviewed backend
docker run --rm --name perspecta-api -e DEBATE_MODE=mock \
  -p 127.0.0.1:3001:3001 perspecta-api:reviewed
```

依据 [Docker 端口发布文档](https://docs.docker.com/engine/network/port-publishing/)，省略宿主 IP 的端口发布默认可能面向所有接口。回环示例不代替平台防火墙、版本和网络检查；官方还列有旧版本及不同网络模式的限制。这里不修改系统 Docker 设置或安装运行时。

- [ ] 镜像使用非 root 用户；仅复制运行源码、JSON 与只读 health 脚本，不带本机私有文件、测试结果或凭据。
- [ ] 实际完成镜像构建、容器 health、关停、资源/网络检查后再记录证据；静态 Dockerfile 审阅不算容器已跑通。
- [ ] 在批准的同源 HTTPS 根地址运行 health。CLI 仅允许 HTTPS 或本机回环 HTTP，不跟随重定向；内部 HTTP 检查可在目标主机通过回环地址执行。

## 4. 入口、前端和错误处理

- [ ] `/api` 前缀原样转发，JSON 状态码、`Cache-Control: no-store`、`X-Perspecta-Mode` 保留，不把后端错误改成 HTML 200。
- [ ] 默认模型超时 45 秒；代理/浏览器等待时间应留余量（如 60 秒），不能无限等。请求头、请求体、keep-alive 的服务端接收超时另行配置，不代表模型超时。
- [ ] 后端不信任用户传来的 X-Forwarded-For；同一代理后的用户共享来源桶。若公开运行，需要在可信入口另定按用户/来源的限制，不能直接信任客户端头。
- [ ] 无登录系统是本版范围决定，不能据此声称公开付费 API 已有身份保护；公开范围与网关访问控制必须先确定。
- [ ] 前端就绪后按 `frontend-integration.md` 联调；没有前端分支时不伪造页面或中断队友。

## 5. live 上线是单独的批准步骤

- [ ] 当前四次调用额度已消耗完；上线持续生成所需的额度/费用、调用范围与部署均要明确授权，不能复用测试锁或自动重启继续测试。
- [ ] 由授权人将 Key 注入服务端，显式选择 provider/model/base URL、超时、输出上限、并发、全局/来源频率、进程调用次数与 token 预算。
- [ ] 首次受控试用先单实例、低并发；本机/进程 token 预留是保守估算，不是货币硬上限。跨实例/重启的费用约束需要目标平台/供应商侧方案。
- [ ] 不在启动、健康探测或异常处理中自动生成。模型 429/预算耗尽不是重启服务的理由：重启会重置内存预算。health 即便额度耗尽仍应检查进程目录，不增加生成。
- [ ] 如果需要实际生成验收，另行批准次数和金额，逐次审阅；失败不自动重试、不降级到其他模型、不把历史案例冒充实时。

## 6. 日志、停止与回退

- [ ] 平台采集结构化 stdout，保留讨论 ID、状态、耗时、实际 usage/usageDetails、上游提供时的费用；不记录请求体、发言、原始上游错误、授权头或环境变量值。
- [ ] 费用需要依据当时价格及实际缓存/输出计数核算；未知金额为 null，不把估算写成已核对账单。
- [ ] 回退前先停止新生成入口，尽量在没有在途请求时切换版本；SIGTERM/SIGINT 会停止接收并等待结束，最多约 5 秒后强制退出。不能把进程退出等同于供应商不计费。
- [ ] 保留旧的已批准版本/配置（不把 Key 放在版本库），回退先以 mock 启动并运行 health；不要靠自动真实重试验证回退。
- [ ] Docker stop/托管停止超时应覆盖本服务退出窗口；长生成可能被打断，目标环境须实际验证这类行为。
