# 2026-11-05 自定义议题与本地用量限制修复

线上旧版本 02c65da 的进程日志共 37 次模型调用，实际累计 186583 tokens；全部调用有用量记录，上游没有 429 或 402。后端要求预留下一次完整提示词与输出上限，因此累计 200000 token 的进程保护在下一次请求前触发。该保护原本不会随时间恢复，与 DeepSeek 账户余额无关，却一直返回“请求过于频繁或服务额度已用完”和固定 60 秒重试提示。被本地保护拒绝的请求没有调用模型。

另一个独立问题：截图中的“学计算机还是学土木”只有 9 个字，旧前后端最少 10 字的规则会拒绝它，并不是限制自定义议题必须命中推荐列表。

## 修复

- 前后端均接受去除首尾空格后 2–300 个 Unicode 码点的议题；推荐议题仍只是快捷填充。
- 增加 `SESSION_BUDGET_WINDOW_MS`。默认 0 继续保留老的进程累计模式；生产 Compose 显式使用 3600000，即每小时自动恢复相同的 200000 token / 100 次调用保护，不提高单窗口上限。
- 处理中请求的预留量和次数会带入下一窗口，完成后只结算一次；未知费用仍按原预留扣减，不因窗口切换丢失在途保护。
- 区分重复请求、并发、分钟限流、次数和 token 保护；本地用量提示明确与模型账户余额不同。`Retry-After` 使用实际恢复时间；永久进程保护不再承诺 60 秒恢复。
- 本地拒绝记录固定原因及恢复时间，不记录议题、来源 IP 或密钥；模型失败仍不自动付费重试。

## 部署

`deploy/compose.yaml` 仅管理 perspecta 项目，保留 8888 端口、独立网络、只读文件、资源和日志限制。沿用 `/home/ubuntu/perspecta/shared/api.env`；新增窗口设置使用 Compose 环境覆盖，不修改该密钥文件或 DeepSeek 模型。

从仓库根目录构建前端时设置 `VITE_API_MODE=live`，然后指定 `PERSPECTA_IMAGE_TAG`，使用 `docker compose -f deploy/compose.yaml build --pull=false api` 及 `docker compose -f deploy/compose.yaml up -d --pull never --force-recreate --wait`。服务器发布目录亦保留独立配置与旧版本供回退。新配置的窗口计数仍在单进程内，重启会重置，不是模型账户的货币硬上限。

新增测试覆盖短议题原样传给假模型、Unicode 边界、用量到期恢复、跨窗口在途预留、失败预留、重复结算、永久保护提示和安全拒绝日志。生产健康检查只读接口；真实自定义议题验收另行记录结果。
