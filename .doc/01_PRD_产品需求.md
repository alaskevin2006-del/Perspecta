# AI 多视角圆桌讨论系统｜产品需求文档 PRD v0.1

**状态**：开发基线（2026-11-03）　**负责人**：林恺欣　**版本目标**：11/3 跑通、11/4 上午打磨

## 1. 产品定义

**目标用户**：面对学业、升学、就业、个人发展选择的大学生，尤其是想同时了解不同思考角度，却缺少高质量讨论对象的同学。

**核心问题**：普通 AI 问答往往输出一份综合建议，难以让用户直观看到不同价值取向的冲突及适用条件；多角色对话如果只是重复表态，又缺少实质内容。

**解决方式**：把一个现实议题交给观点不同的 2–3 位角色，通过“独立陈述 → 针对回应 → 分歧总结”的结构，展示不同选择背后的假设、理由和代价。

**产品定位**：供思考与比较的模拟讨论工具，不是现实人物发言平台，也不提供权威的升学、就业预测。

## 2. 首版用户旅程（唯一主流程）

1. 打开页面，看到推荐的大学生现实议题，或输入自定义问题。
2. 选择 2–3 个讨论角色；每张角色卡显示其关心的核心问题与视角。
3. 点击「开始圆桌」，进入加载状态；生成完成后按轮次逐条播放文字讨论。
4. 第一轮：每人说明**立场、理由、成立条件**。
5. 第二轮：每人明确引用并回应另一人的一个具体论点，补充反例或约束，不允许无意义附和。
6. 展示结构化总结：**共识、核心分歧、决策变量、下一步可做的事**。允许复制内容。

## 4. 内容初版

### 推荐议题

- **考研还是就业？** 对大二学生而言，什么时候开始决定更合理？
- **绩点还是项目实践？** 时间不足时，优先级如何确定？
- **稳定还是探索？** 大学生应尽早锁定方向，还是多尝试不同可能性？

### 默认角色（临时原型，可替换）

- `career_realist`：现实规划派；强调资源约束、机会成本与结果可实现性。
- `growth_explorer`：成长探索派；强调兴趣、长期能力、试错空间与自我认知。
- `risk_analyst`：审慎权衡派；强调信息不足、选择的可逆性和条件差异。

**待产品负责人决定**：是否以有公开素材依据的具体公众人物替换这些原型。这个决定不阻塞前后端开发，角色数据层可替换即可。

## 5. 页面结构

- **顶部**：产品名称 + 一句话说明（“让不同视角帮你看清选择的代价”）。
- **左侧/上方操作区**：推荐议题、自由输入、角色卡、开始按钮。
- **中间主视图**：角色头像/颜色区分 + 圆桌讨论消息；消息标记轮次。
- **底部/侧栏**：结构化结论；按钮「重新讨论」「复制结果」。
- **状态**：未开始、生成中、生成成功、生成失败。生成失败要提示重试，不能出现空白结果。

具体布局由刘智华决定，优先保证 1366×768 笔记本屏幕完整可用；不要求复杂动画。

## 6. 讨论质量约束（产品核心）

每条第一轮发言必须包含：观点 + 1–2 条理由 + 适用条件；第二轮必须明确指出回应谁的哪个论点，并给出反驳、补充或限定。禁止空泛口号、无依据具体数字、杜撰真实人物原话。总结应列出 **什么条件下哪种选择更合适**，避免绝对化裁决。

为控制时延与成本，默认 **3 位角色 × 2 轮，每条 60–140 个汉字，总结每个字段 1–3 句**。生成一次完成，前端逐条展示；“逐条展示”不等于后端逐个实时调用。

若引用真实人物资料，界面必须标记为“基于公开资料的 AI 模拟观点”，并保存引用来源，不能宣称“真实人物正在参与讨论”。

## 7. 非功能要求

- API Key 仅放服务端环境变量，前端不得暴露。
- 服务端校验议题长度、角色 ID 数量和白名单；请求超时与重试次数有限制。
- 不保存用户敏感对话；演示阶段可不做账号、数据库及长期历史记录。
- 后端记录每次调用的耗时、Token 用量和费用（如果提供商返回），至少能人工检查成本。
- 预设话题和角色信息可作为本地 JSON 管理，不依赖在线数据库。

## 8. 最终演示路线

用“绩点还是项目实践？”演示：点选话题 → 选择三种立场 → 开始 → 展示第一轮立场 → 展示第二轮针对性交锋 → 重点展示总结中的决策变量（如升学目标、项目质量、剩余时间）。

**产品负责人验收重点**：是否有真实争点与权衡，而不仅是三个人轮流说看似正确的话。
