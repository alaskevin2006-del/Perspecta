# Perspecta 前端

Perspecta 是一个多视角圆桌讨论页面，使用 React、TypeScript 和 Vite。用户写下问题，邀请 2–4 位嘉宾，观看四阶段连续讨论，并保存结构化的思辨札记。

## 启动与校验

在本目录安装依赖并启动：

```powershell
npm ci
npm run dev
```

打开终端输出的本地地址。

```powershell
npm run typecheck
npm test
npm run build
```

生产构建输出到 `dist/`。部署时由静态服务器提供前端文件，并将同源 `/api` 请求转发给后端。

## 当前页面

- 顶部提供“圆桌讨论”和“关于我们”入口，品牌标志为静态展示。
- 左侧支持输入 10–300 字的问题、选择推荐议题，以及邀请 2–4 位嘉宾。
- 勾选嘉宾时显示头像预览；点击“开启这场对话”后确定本场名单，并加载对应人数和组合的对谈场景。
- 等待期间显示“观点正在酝酿，请稍候…”，暂时锁定议题与人选。
- 后端一次返回完整讨论，前端逐条播放四阶段发言，支持暂停、继续、下一位和跳过播放。系统开启减少动态效果时，使用手动推进。
- 右侧展示可折叠讨论记录，完成后可切换“思辨总结 / 讨论记录”。总结包括主要共识、核心分歧、关键变量、下一步行动。
- “保存为图片”使用独立札记模板生成 PNG，提供图片预览与下载；“复制完整讨论”包含议题、全部发言及总结。
- “调整议题与嘉宾”经确认后清除当前结果，保留问题与嘉宾选择。
- 长议题可在书页内滚动阅读。舞台为 1671×941 固定构图，随窗口整体缩放；目前以电脑端使用为主。

## 接口约定

默认使用本地模拟数据，不请求后端或模型。演示发言为固定文案，自定义问题仅回显，不会针对新问题实时生成。

| 方法 | 路径 | 请求／响应 |
| --- | --- | --- |
| GET | `/api/roles` | 返回 `{ roles: [...] }` |
| GET | `/api/topics` | 返回 `{ topics: [...] }` |
| POST | `/api/debate` | 提交 `{ topic, roleIds, rounds: 4 }`，返回完整讨论及总结 |

数据类型及校验规则见 `src/data.ts`，详细字段见 [前端说明](.doc/04_前端开发PRD.md)。请求超时为 **60 秒**（后端模型时限保持 45 秒，预留 15 秒处理和传输余量），失败显示错误并保留输入，不自动重试、不自动切换模拟结果。没有 SSE 或实时生成进度百分比。

前端读取成功响应头 `X-Perspecta-Mode: mock|live`。目录接口决定讨论开始前的说明，本场讨论响应决定结果和图片导出的说明。缺少标识、标识非法或目录接口的模式不一致时，显示“数据模式待确认”。本地演示固定标记为 mock。

## 切换为请求后端

在未提交的 `.env.local` 中设置：

```dotenv
VITE_API_MODE=live
```

`live` 在这里只表示请求后端；后端是否调用模型，以实际响应头为准。产品固定支持 2–4 位嘉宾，前端允许提交四人请求；整合后端支持四阶段，2/3/4 人分别为 8/12/16 条发言。

当前 `vite.config.ts` 的默认代理目标为 `http://127.0.0.1:3001`。默认已对齐后端的 3001 端口；若需要显式指定或使用其他地址，可在 PowerShell 设置代理目标后启动前端：

```powershell
$env:API_PROXY_TARGET = "http://127.0.0.1:3001"
npm run dev
```

代理目标由 `process.env.API_PROXY_TARGET` 读取；请在启动终端设置该变量。配置变更后需要重启开发服务器。同源代理应保留 `/api` 前缀及模式响应头。模型密钥只配置在后端。

## 连续辩论协议增量（2026-11-04）

当前页面显式请求 `rounds:4`：抛出争点、质疑与反例、回应与修正、条件与未决，每阶段每人一条。首阶段各人提出立场，后续混合跨轮回应；第三阶段回接别人对自己早前论点的回应。用户只能在开始前输入议题，播放中可暂停、推进、跳过，暂不支持中途发言。

未带 `rounds` 的旧请求仍两轮；显式 `rounds:3` 保留队友三轮模式，第三轮至少一次回应第二轮。接口返回字段不变。严格结构检查不能代替内容与画像验收，mock 固定文案也不能证明真实辩论质量。
